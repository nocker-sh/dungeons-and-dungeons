# 演出時間と再現のルール

ゲームとプレビューは同じ GameApp、画面、BattleDirector、エフェクトを使う。プレビュー専用の似せた画面・戦闘規則は作らない。差し替えるのは初期状態、保存先、乱数、時計、操作の台本。コンポーネントの展示も本物の部品を使う。

## 制御の原則

ゲーム画面の再生はMotionへ統一する。Reactの登場・退場・繰り返しは `motion/react`、命令的なDOMの動きは `components/canvas/play.ts` 経由の `motion/mini`、数値・文字送り・カメラはMotionの数値アニメーションとフレーム処理を使う。ゲーム画面にCSS transition、手書きの補間ループ、完了を推測する `setTimeout` は置かない。フォーカス位置の測定や開発用の仮想時計は演出の完了判定とは別。

`components/canvas/animation.ts` の `parallel` は同じ拍で始める再生を所有し、有限の演出がすべて完了するまで待つ。`after` は前の再生の成功後にだけ次の処理を始める。見せる長さ・遅延・イージングは各演出の定義と `stage/timing.ts` に置けるが、その値を別の待ち時間に複製しない。開始位置の指定や読書のための保持が必要ならMotionの `hold` を使う。

- ダメージ数がHPへ到着 → 味方のHP数字とゲージの更新・必要なら敵の退場（敵のHPは画面に出さない） → 手番後の出来事 → 勝敗 → 次の指示、の順に完了を待つ。意図的に重ねる同じ拍の動きは並列に再生する。
- 味方のHP・防具は結果を見せる間だけ直前の表示を保ち、結果表示後に数字とゲージを更新する。その再生完了も手番の待ち合わせに含める。表示用の参照だけを保持し、ゲーム規則・操作可否の状態は複製しない。
- 入力中は同期的なロックを持ち、連打で同じ行動を重ねない。エンジンの結果確定と、結果を見せ終わる時点は区別する。
- `AnimationScope` と `AbortSignal` を画面・操作の寿命へ結び付ける。中断した再生の完了通知ではHP更新・退場・画面遷移を起こさない。同じ要素・プロパティを新しい再生で置き換えるときも、古い待ちを明示的に解放する。
- 漫画画像の `ComicEffect` は `/dev/effects` と実戦で共有し、`play` の実際の完了を `FxStore` へ返す。画像は戦闘の指示開始前に読み込み、スタジオでも仮想時計を開始する前に読み込む。動きを減らす設定では移動・回転・拡大を止め、有限のフェード完了後に手番を進める。攻撃に伴う毒などの文字はダメージ数字の到着を待ってから表示する。
- `useRun` はエフェクト内部の有限の再生をすべて待ち、背景の無限ループはエフェクトの終了・中断と一緒に止める。DOMから取り外した命令的アニメーションも停止する。
- 非表示の要素には再生を開始しない。実際の再生エラーを「完了した」として隠さない。
- 画面の退場はMotionの開始・完了通知を共通の待ち合わせへ登録する。ナビゲーションは退場とカメラの両方を待つ。
- 出撃の黒帯はStageが所有し、「閉じた」時点で次の画面へ進む。次の画面が「開く」合図を出すので、遷移元が黒帯全体の終了を待って相互待ちにならないようにする。

## 演出時間の基準

通常の画面到着は450ms、登場は420ms、退場は240ms。場所画面で行き先（入口の吹き出し・宿の部屋の札）を選ぶと、背景のその場所を画面の中央へ運びながら背景を2.2倍へ420msで寄せ、要素は同時に240msで退場する。次の画面は寄る動きの続き（dolly：ぼけた寄りから落ち着く）で受ける。寄る位置・倍率・時間は `stage/focus-zoom.ts` と `stage/timing.ts` の `focus` に一元化し、場所ごとに数値を置かない。動きを減らす設定と `?still` では寄らず、要素の退場だけで切り替える。戻る操作は既存の引き（380ms）のままにし、行き先へ寄るズームの逆再生は入れない（戻りは短く済ませる）。文字は280msで着地し、文字全体のずらしは最大180ms。長い名前ほど遅くなる状態を避ける。押した反応は100ms、選択の切り替えは180msを基本にする。

カットインは通常800ms、節目1100ms。スキル立ち絵は760ms。指定時間を持つ演出はその指定を尊重する。繰り返しの呼吸・背景の動き、ユーザーが読む会話や報酬の表示時間を一括で短縮しない。

戦闘の数字は720ms、ダメージの移動は560ms、HPの数え直しは180ms。衝突80ms後にダメージを出し、数字がHPへ到着する640ms後にHPを更新する。倒れた敵の退場240msを含め、最後の対象の演出完了後60msで次の手番へ進む。標準の単一対象の目安は940ms（HPを数え直し、倒れれば退場する場合までの上限）、複数対象は60msずつずらす。敵のHPは画面に出さないので、倒れない敵への一撃は被害の数字を見せ終える860msが目安。実際の完了条件は再生ハンドルで、停止・延長された演出をこの目安で打ち切らない。状態異常や防具の後に出る文字は、その遅延と表示完了も待つ。白い残像ゲージは60ms遅延＋180msで追いつき、数字の拡大も180msで戻る。HP変更のタイマーが次の手番や画面へ漏れないことを確認する。

## 画面の切り替え（有限オートマトン）

画面の切り替えは [[client/game/screen-transition.ts]] の状態で進める（React・DOM に依存しない）。

```text
showing ──go──▶ leaving ──left──▶ arriving ──arrived──▶ showing
```

- showing：画面を表示して操作を受け付ける。切り替えを始められるのはここだけ。切り替えの途中に来た `go` は受け付けない（二重の切り替えで画面が混ざらない）。
- leaving：今の画面の要素が退場し、カメラが動く。次の画面はまだ描かない。
- arriving：次の画面を置く。背景は読み込みと展開（decode）が済むまで前の絵を出したまま、済んだら一度に差し替える（`stage.art` が差し替えて次の描画を終えてから解決する）。そのあと入りのショットを撮り、`useArrival` が `arrived` を送る。画面の要素は背景を差し替えてから描くので、古い背景の上に新しい画面が乗る一瞬や、読み込み中の黒い隙間を作らない。
- 最初の画面も arriving から始める。決めた遷移以外のイベントは状態を変えない。

## 検証

- /dev/studio の0ms、中間、完了時刻をスマホ390×844と横長1280×800で撮影する。
- 同じシナリオのゲーム状態・操作・演出開始/完了時刻が一致することを確認する。
- 通常の /previews は実時間で再生する。静止画用の ?still は別の明示的なモード。
- 戦闘のスキル・通常攻撃・防御・敵の手番、施設内の会話・募集・召喚を実際に操作する。
- `vp test run`、`vp run typecheck`、変更箇所の整形・lint、`vp build` を通す。
- `vp run e2e:timing` で既存のHP・行動順の契約、`vp run e2e:animation` で実再生を停止・再開したときの順序と二重入力を確認する。
- `vp exec bun tests/e2e/battle-effects.ts` で画像演出自体の停止・完了待ち・再開と、動きを減らす設定での手番完了を確認する。
- 共通再生の単体テストでは、完了通知の遅延、並列の片方だけの完了、中断、同じプロパティの置換、DOMの取り外しを確認する。

基本画面だけを「全状態」と呼ばない。内部メニュー、探索の宝箱・罠・戦利品、勝敗や購入など操作で発生する演出は、開始状態または操作台本を持つシナリオで検証する。

## 条件付き会話の立ち絵とセリフ枠

通常プレイとdevは共通のEventConversationView / Conversationを使う。場所に立つ店主・案内人（Guide）は、ゲーム状態が会話中の間は退場の演出で隠れ、会話が終わると登場の演出で戻る。会話の立ち絵の後ろに白い板は置かず、透過の上半身を背景の上へ直接出す。立ち絵は最初は画面下に隠し、セリフ枠のMotion登場完了通知を受けて上へ登場する。終了時は立ち絵の退場をawaitし、その後で枠を閉じる。枠の退場完了後に会話を終了する。登場中と終了処理中の送り操作は受け付けず、固定時間のsleepで順番を推測しない。
