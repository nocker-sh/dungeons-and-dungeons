# ダンジョンズ & ダンジョンズ！

公開する開発・設定資料。確定仕様、実装の受入条件、制作案を区別し、ゲームの結末や未決定事項を補完しない。画像本体と手元の制作環境は同梱しない。

## ジョブ

- プレイヤー: 仲間と装備を育て、3人で短い判断の繰り返しでダンジョンを突破する。

## ビジョン

編成・戦利品・成長・仲間への愛着を、「進む」「戻る」の探索に凝縮する。

## 解決する問題

- 空間移動の手間を省き、次の出来事と帰還判断へ集中できるようにする。
- UIに規則が散らばることを防ぎ、ゲームの詳細を独立して変更・検証できるようにする。

## ターゲット

- 短い時間で抽選、戦闘、収集、成長を楽しみたいプレイヤー。

## 原則

- ダンジョンの移動は進む・戻るだけ。進むごとに抽選し、節目には固定戦闘を置く。
- 3人編成（前衛2・後衛1）。後衛も攻撃できるが、後衛から近接で攻撃すると被害は半分。敵の近接は前衛にしか届かず、遠距離は後衛にも届くが当たりにくい。戦闘は各キャラに指示し、1行動ずつ結果を見せる。キャラクターの合成は行わない。
- 仲間は求人、武器はガラクタ鑑定と店で獲得する。武器集めを中心の楽しみにする。
- 宿で回復し、汚れ・疲れを整える。仲間との会話と育成を持つ。
- Reactとゲーム規則を分離する。クラスと明示的なDIで拡張する。
- スマホ優先、PCでは中央配置。画面は一手一幕の演出で見せる。未用意の画像だけ色付きの仮表示を使う。

## やらないこと

- 課金、ネットワーク同期は扱わない。画像はユーザーが用意するか、ユーザーの依頼で [[image-generation|画像生成のルール]] に従って生成する。
- ゲーム状態をReactのローカル状態へ複製しない。

## 技術スタック

- TypeScript / Vite+ / Void: 既存のアプリ構成と検証経路を利用する。
- open-wizのローカル複製: 既存の不変状態・トランザクション・保存検証を再利用する。
- Zod: 操作、静的定義、保存データを信頼境界で検証する。
- React Context / useSyncExternalStore: エンジンを注入し、同じ状態を購読する。
- 画面演出: Canvas部品・style属性・motion/reactで描画し、ゲーム画面をページ側のCSSから分離する（[[decisions/003-mock-into-app|003]]）。
