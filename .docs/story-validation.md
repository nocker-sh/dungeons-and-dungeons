# 物語の自動検証

物語を変更するときは、開始条件・選択肢・状態変化・得るもの・繰り返した結果を、本番データと実際の進行処理に対するテストへ反映する。テスト専用の進行規則や台本を作らない。乱数・時計・ID・保存先などの外部境界だけを固定する。

`vp run test:story` はブラウザなし、1ワーカーで会話のデータ検証・条件判定・実操作・保存再開の検査を実行する。全体テストにも同じ検査を含む。重い検査は直列で行い、ブラウザ確認は並列実行しない。

## 条件の検査と到達の検査

会話を読み込む入口は、ID・話者・場所・進行度・要求フラグの生成元を照合する。同じフラグを要求と除外の両方に指定した台本は、開始不能な条件として拒否する。実データを変えて入口が拒否する回帰テストも保つ。形が正しいことと、実際にその状態へ到達できることは別に検査する。

条件を与えた制作画面のシナリオは、その条件下の表示と操作可否を確かめるために使う。途中の進行度やフラグを直接与えた試験を、最初から到達できる証明へ読み替えない。実進行の検査は新しいゲームから本物のコマンドを送り、会話の開始と完了で生まれた状態を次の操作へ渡す。

`onboarding.test.ts` は新しいゲームから開幕の会話と選択肢を列挙して実操作で辿り、到達した台本と回答の集合を本番データの全件と照合する。選択で立つフラグを確認し、街へ出る・名前を登録する・受付の会話を終えるまで進める。実際に通った状態と遷移から、探索したどの状態にも開幕を終える経路があることを照合し、終端のない閉路を成功にしない。各操作後の保存をJSON経由で復元し、同じ初期状態と乱数・操作列から再実行した状態・会話の問い合わせ・イベント・保存結果が一致することも確認する。

`play-event-conversation.test.ts` は本番の開幕・登録・受付の会話から昇降機番の会話中の保存を作り、新しいエンジンへ復元する。画面側の待機処理が再開中の同じ会話を待ち、実際の会話完了後に初出撃でき、探索の問い合わせと状態が一致することを確認する。中断・無関係な会話・既に完了した訪問では進行や乱数を変えない。通常の話しかけと複数人の共有会話の相手判定は、条件を明示した本番台本の局所検査であり、最初からの到達検査とは分ける。画面全体の移動演出と描画は対象外。

`town-quest-progress.test.ts` は本番の討伐依頼を受け、街の戦闘中に保存して新しいエンジンで復元し、同じ敵の撃破が一度だけ数えられることを実操作で確認する。街の依頼の自動精算と報酬も保つ。未受注・対象違い・未撃破・必要数の上限・報告済み・ボス限定・勝利時の生存条件は別のケースで確認する。拒否された操作や完了後の保存再開で、進捗や資産が増えないことも確かめる。

`victory-settlement.test.ts` は本番の敵と初期装備を使い、実際の戦闘で作った決着直前の保存から、同じ環境入力で同じ報酬へ進めることを確認する。勝利直後の保存再開、決着行動の再送、戦利品確認の再送、帰還の再送を通して、金貨・経験値・所持品・落とした装備が二重に精算されないことを検査する。戦闘開始は局所的な初期条件であり、そこまでの探索経路や全ての敵・乱数列を検証したものではない。

`claim-quest.test.ts` は本番データの通常討伐依頼を全件列挙し、受注の再送、必要数の1体手前での報告拒否、達成時の金貨・品物の一度だけの精算を実エンジンで検査する。報告前後の保存をJSON経由で別のエンジンへ復元し、問い合わせの未達成・報告可能・報告済みと操作結果の一致、再報告・再受注の拒否による全状態の保持を確認する。討伐数と踏破条件は局所的な初期条件として与えており、討伐経路や踏破への到達を証明する検査とは分ける。

`shop-save-roundtrip.test.ts` は店と商品の組み合わせを本番データから全件列挙し、解放前・代金の1不足・代金ちょうどの表示と実際の購入判定を照合する。購入した武器・防具・袋の品物・召喚石をJSON保存から別のエンジンへ復元し、所持数量と売却候補・売値を確認する。売却不可、拒否した購入、売却後の保存再開と二重売却では全状態を保持する。到達層と所持金は局所的な初期条件として与え、そこまでの探索や資金調達の経路とは分ける。

`demon-contract-resumption.test.ts` は契約を持つ本番の悪魔を全件列挙し、実際に呼び出せる相手から会話と契約を進める。友達の加入などの前提は先の契約で満たし、出会い済みの印を直接足さない。会話中のJSON保存再開、再呼出しの拒否、出会い後の再会で契約書を再消費しないこと、必要資源の不足、表示と契約結果、契約後の再開と再送を検査する。全対象を契約できなければ未対応や依存の矛盾として失敗する。登録済み・到達層・契約書と資源は局所的な初期条件であり、登録・探索・契約書の入手経路や全ての契約順を証明する検査とは分ける。

`smithy-save-roundtrip.test.ts` は本番の全生産レシピを実行し、作った未装備の武器・防具を正本の全強化段階まで育てる。各支払いの前に代金と各素材の不足を局所条件として与え、表示が実行を許可しないことと、拒否で全保存が変わらないことを確認する。成功時の代金・素材・個体・強化段階を照合し、各段でJSON保存から別のエンジンへ復元して表示も比較する。上限では追加強化を拒否し、全工程の必要量だけ用意した資源がちょうど尽きることを確認する。登録済み・街・開始資源は局所条件で、採集や資金調達、装備中の能力変化、固有武器の鍛え直しの検査とは分ける。

## 検査の境界

会話の問い合わせとエンジンの状態を確認しても、全台本への到達、全フラグの組み合わせ、全探索経路、演出が終わるまでの時間、最終的な画像は、この検査だけでは証明しない。配置・読みやすさなど、出力データだけでは判断できない変更に実画面の確認を使う。
