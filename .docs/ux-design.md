# ゲームUX設計

## 体験の目的

短い間隔で出来事・戦利品・成長に触れ、欲しい報酬と残りの体力を見て進むか戻るかを選ぶ。仲間と装備を育てた結果が、以前は戻った場所の先へ進めることとして伝わる設計にする。

確定した規則は[[game-spec]]、操作の受入条件は[[features]]、画面の関係は[[sitemap]]、見せ方は[[ui-direction]]を正とする。この文書はそれらを採用する体験上の理由を扱う。

## 一周の流れ

街で必要な支度をし、街はずれの乗り場で到達済みの層を選ぶ。昇降機から探索へ入り、一歩ごとの結果を確認する。継続・分岐・帰還を選び、帰還後の収集と成長を次の挑戦へつなげる。

- 街は安心と次の挑戦への期待を持つ場所。出撃前に不要な確認を重ねない。
- 乗り場は前回の到達と今回の行き先を確認する場所。未到達の具体を先に明かさない。
- 探索は体力・報酬・危険を比較する場所。一歩で複数の結果を同時に処理させない。
- 戦闘は各人の指示と、その結果を一つずつ見る場所。入力待ちと演出中の状態を区別する。
- 帰還は持ち帰れた物と成長を受け取る場所。現在の全滅時の損失は実行ルールを参照し、失敗をキャラクターの永久喪失にしない。

## 操作の構造

一画面には一つの主目的を置き、主操作を最も目立たせる。品物や仲間を詳しく見たいときだけ詳細へ進み、閉じたら元の対象とフォーカスへ戻る。常設の説明板で主画面を埋めない。

街の移動、施設の用事、品物の詳細を階層として区別する。探索中の「戻る」は帰還であり、詳細画面の「戻る」と同じ結果にしない。戦闘・探索から街の買い物や募集を直接操作できるようにしない。

購入・売却・装備などの操作は、必要な資産と操作後の変化をその場で確認できるようにする。拒否された場合は理由を示し、資産や状態を変えない。保存に失敗した場合は、現在の遊びを保ちながら再試行できるようにする。

## 情報の優先順位

- 探索では次の判断、残りの生命力と防具の耐久、持ち帰る価値を優先する。
- 戦闘では現在の指示対象、使えるワザと残り回数、届く対象、演出中の結果を優先する。廃止したMPを表示しない。
- 隊列は3人・前衛2人と後衛1人。仲間の詳細は必要なときに開き、初期準備に詳細確認を必須としない。
- 未鑑定・未到達・未契約を区別する。未確定の能力や抽選結果を確定値のように見せない。

## スマホと入力

スマホの縦画面を基準にし、横画面では同じ目的と操作を保って配置を変える。小さい文字や重なったタップ領域で判断を妨げない。スクロールは一覧の内側に閉じ、詳細や会話が開いている間は背面へ入力を流さない。

キーボード・ゲームパッド・タッチのいずれでも現在の対象が分かり、閉じた後に操作位置を失わない。入力方式ごとの受入条件は[[features#キーボード操作]]に従う。

## 演出とテンポ

1行動の結果が次の行動と混ざらないようにする。会話の登場中や戦闘の結果確定前に入力を進めず、完了通知で次の操作を開く。動きを減らす設定でも情報と操作を失わせない。

体験の確認は[[dev-studio]]で固定条件を作り、[[verification]]の手順で実際に操作する。画面が開いたこと、操作できること、気持ちよいテンポであることを別々に確かめる。
