# 検証の入口

現在の仕様は[[game-spec|ゲーム仕様]]、受入条件は[[features|機能一覧]]。過去の成功件数や一時的な失敗を、現在の実装状態の根拠にしない。

## 変更に対応する確認

| 対象 | 確認 |
| --- | --- |
| 型と静的解析 | `vp run typecheck`、`vp run lint` |
| 動作 | 変更した責務の既存テストと、その境界の呼び出し側を実行する |
| ビルド | `vp run build` |
| 数値・ワザ・敵・規則 | `vp run cli check`。測定条件は[[builder/README|builderの手順]] |
| 世界・部屋・人物の資料 | `vp run check:concept` と、正本・本文・生活動線の照合 |
| 画面と演出 | [[dev-studio|スタジオ]]の固定条件で再現し、実際の操作と描画を確認する |
| 画像 | [[image-generation|画像生成のルール]]に従い、元画像・公開画像・実行参照・台帳を照合する |

実行していない確認を成功に含めない。スキップ、環境の障害、実装の失敗を分ける。失敗を消すために期待値・画像比較・タイムアウトを緩めない。

## 記録として残すもの

- 再現条件、原因、修正方針、現在も残る制約。仕様の判断は該当する仕様書へ一度だけ記す。
- 画像の同一性・出典・差し戻し・人の承認は[[concept/data/images.json|実行用画像とレビュー状態]]と個別の設定資料に残す。自動検査やAIの確認を人の承認へ読み替えない。
- 毎回の成功件数、修正の実況、一時的なログの全文は資料へ追記しない。実行結果はその作業の報告で伝える。

詳しい操作方法は[[development|開発と検証]]を参照する。

資料と公開プロンプトのリンク形式・参照先・見出し、非公開参照と端末固有パスの混入は `vp run check:docs` で確認する。自動検査は文章の正確さや作品の魅力を保証しない。
