# 001: open-wizをローカル複製し、作品用ルールを合成する

## 状況

ユーザーは v0-text-world のWizを完全複製して利用できるか検討するよう依頼した。対象は lib/open-wiz。読み取り時のHEADは 79585c59a4305fe1ce620bdb23efc685d0e0b4b2。元リポジトリには書き込んでいない。

既存エンジンはUI非依存のTypeScriptライブラリで、汎用カーネル、標準RPG、値オブジェクト、保存codec、モックを持つ。移植直後に既存150ファイル・1,953テストが成功した。

## 判断

lib/wiz/core に全TypeScriptソース・テスト・README・ARCHITECTURE・MITライセンスを複製する。合計437ファイル。ビルド生成物、node_modules、元リポジトリ専用のパッケージ公開設定は取り込まない。

importの移設と、厳格な未使用検査への対応2箇所を移植差分とする。provenance.jsonへ元ファイルとローカルファイルのSHA-256を記録し、テストで内容を照合する。既存ソースの整形は保持する。

作品側のWizDefinitionは汎用WizWorldへ操作ごとのクラスを合成する。標準RPGを一括起動せず、作品固有の街・探索・戦闘・結果と3人編成を定義する。成長、環境トランザクション、イベント、所有権、保存codec、構成のfingerprintは既存機能を使う。

## 理由

- 全面新規実装: 不変状態、失敗時の乱数巻き戻し、保存検証などの実績を捨てるため選ばない。
- 元の標準RPGをそのまま起動: 空腹・AP・エリア探索など異なる前提があり、今回の二択探索を制約するため選ばない。
- npm参照のみ: ユーザーが求めるローカル改造とソース所有に合わない。
- 全ソース保持と汎用カーネルの実利用: 既存資産とテストを残し、作品側の変更を小さく保てる。

## 結果

coreの全機能が現時点で画面から使われるわけではない。保存・成長・カーネルは実際のプレイ経路で使う。未使用の標準RPG機能も今後の移植判断のため保持する。

エンジンはReact、DOM、画像、作品コンテンツ、localStorageをimportしない。React Contextはユーザーの明示指示に従って採用し、セッションとカタログだけを注入する。状態はuseSyncExternalStoreで購読し、React側のReducerへ複製しない。UIのタブ等はUI内で所有する。

モックは乱数・ID・時計と必要な計算規則を差し替える。DIコンテナは使わない。計算規則を差し替えた構成にはrulesRevisionを要求し、異なる規則のセーブを混同しない。コンテンツ変更も保存identityに反映する。

Storybookの新規導入は行わず、今回の最小UIにはContext接続テストと実ブラウザ検証を使う。詳細な表示状態のカタログ化はUIを詰める工程で判断する。
