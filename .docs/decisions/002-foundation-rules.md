# 002: 暫定ルールを、確定要件と分けて育てる

## 状況

最初の一周を実際に遊べる形で作り、その後で戦闘・成長・経済を調整する。検証のために置いた数値や自動方策を、作品の確定要件へ昇格させない。

確定した動作は[[game-spec|ゲーム仕様]]、受入条件は[[features|機能一覧]]。現在の数値・会話台本は `content/data/`、名前・紹介・画像参照は `concept/data/` が正本。この文書に同じ一覧や数値を転記しない。

## 判断

- 編成は3人・前衛2人と後衛1人。仲間は求人で集め、キャラクター合成を作らない。過去の4人編成を前提にした調整は採用しない。
- 戦闘の役割は相手の数・耐性・射程・探索中の消耗で変わる。全編成を同じ勝率へ揃えることや、固定の一組だけで全てを解決することを調整の目的にしない。
- 周回して武器とレベルを揃える意味を持たせ、稼ぎが次の強さへつながる経路を作る。現在の購入・鑑定・強化・生産の条件は実行用データとエンジンを参照する。
- 武器の個体・ワザの選択・使用回数を育成の判断に使う。枠数などの決定はゲーム仕様を参照し、過去の調整案を並行した仕様として残さない。
- 道中の配置事故と、最終ボスの難しさを分けて評価する。HPを増やして長引かせるだけの解決は避け、被害・戦闘の長さ・再挑戦の間隔を別に見る。

## 自動計測とプレイヤーの操作

計測の街準備は方策の一部。前衛・後衛の比較や買い物を変更した場合、同じ種と所持品の条件で比較する。自動方策の配置判断を、ゲーム画面でプレイヤーが選んだ配置の自動変更に使わない。

レベル・所持金・回復薬を与える測定用の準備は、通常の資金繰りや入手難度とは区別する。攻撃強化の比較には実際に使えるワザ・射程・強化の結果を含め、武器の素の攻撃力だけで判断しない。

数値や方策を変えたら `vp run cli check`。測定条件と操作は[[builder/README|builderの手順]]を参照する。自動方策の合格を、人が遊んだテンポの評価や確定仕様と同一視しない。

## 残す判断の範囲

データの更新で変わる数値、過去の成功件数、調整の実況はここへ積み上げない。制約・判断理由・採用しなかった方針のうち、次の設計判断に必要なものを残す。
