# 003: 画面コンセプトをゲームへ統合する

## 背景

画面コンセプトでは、配置・カメラ・登退場・1行動ごとの結果表示が遊びのテンポを作る。既存の汎用UIへ見た目だけを載せると、演出の寿命とゲーム進行が別々に動いてしまうため、画面と操作の接続を設計し直す必要があった。

## 判断と理由

- ゲームの状態・操作・保存は独立したエンジンが所有する。画面コンセプトの数値や台本を、そのまま確定ルールにしない。
- ゲームは単一URL内の場面遷移として扱う。開発用のデータ閲覧・プレビューは独立したURLを持ち、ゲーム内の進行状態と混同しない。
- ゲーム画面はCanvas部品・style属性・motion/reactで描画する。部品をページ側のCSSから分離し、演出の接続を保つ。開発画面はshadcnを使う。
- 基盤はopen-wizの汎用カーネルを再利用し、街・探索・戦闘・3人編成の操作と規則は作品側で合成する。既成の標準RPGの画面・移動・装備の前提へ作品を合わせない。

## 現在の適用範囲

探索、戦闘、街の施設、育成、会話を同じ操作経路へ接続する。演出はエンジンが確定した出来事を再生し、表示途中の値をゲーム状態へ書き戻さない。仮想時計と固定条件で実画面を再現する。

現在の遊び方は[[game-spec]]、受入条件は[[features]]、責任分担は[[architecture]]、演出は[[animation-rules]]、検証操作は[[dev-studio]]を参照する。過去のモックや移行時の状態を現行仕様の正本にはしない。
